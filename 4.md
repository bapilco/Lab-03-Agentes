# Parte 4 --- Mejora del agente con LangGraph

La implementación se encuentra en `myagent_langgraph.py`, dentro de la
clase `MyAnalystAgentLangGraph`.

------------------------------------------------------------------------

## Implementación

El agente se construye mediante `StateGraph` y utiliza los siguientes
nodos:

-   `modelo`: realiza la llamada al modelo y decide si debe responder o
    utilizar una herramienta.
-   `herramienta`: ejecuta la herramienta solicitada.
-   `responder`: genera/retorna la respuesta final.
-   `tope`: finaliza cuando se alcanza el máximo de pasos.
-   `token`: finaliza cuando se alcanza el presupuesto de tokens.
-   `repeticion`: finaliza cuando se detecta repetición de la misma
    herramienta con los mismos argumentos.
-   `error`: finaliza una ejecución ante un error no recuperable.

El flujo principal es:

``` text
START
  |
  v
modelo
  |
  +----> responder ----> END
  |
  +----> token --------> END
  |
  +----> error --------> END
  |
  v
herramienta
  |
  +----> modelo
  |
  +----> tope ---------> END
  |
  +----> repeticion ---> END
  |
  +----> error --------> END
```

El diagrama también fue generado directamente a partir de
`agent.graph.get_graph().draw_mermaid()`, por lo que representa la
estructura real del `StateGraph`.

------------------------------------------------------------------------

## Condición de parada

El agente puede terminar por cuatro caminos principales:

1.  El modelo produce una respuesta final.
2.  Se alcanza el máximo de pasos.
3.  Se alcanza el presupuesto de tokens.
4.  Se detecta una repetición de la misma herramienta con los mismos
    argumentos.

Además, un error no recuperable conduce al nodo `error`.

El límite de pasos se implementa como una arista explícita hacia el nodo
`tope`, en lugar de depender únicamente del `recursion_limit` de
LangGraph.

------------------------------------------------------------------------

## Herramientas

El agente mantiene las tres herramientas de la implementación anterior.

### `execute_query`

Consulta la base SQLite utilizando únicamente operaciones de lectura.

Restricciones principales:

-   Una sola sentencia.
-   Solo `SELECT` o `WITH ... SELECT`.
-   Base abierta en modo solo lectura.
-   Máximo de 50 filas controlado por el código.
-   La ruta de la base no es un argumento controlable por el modelo.

Devuelve:

``` json
{
  "columns": ["..."],
  "rows": ["..."],
  "row_count": 1
}
```

o, ante un error:

``` json
{
  "error": "..."
}
```

### `compute_statistics`

Calcula estadísticas descriptivas sobre los datos obtenidos mediante
`execute_query`.

Puede trabajar con las columnas numéricas seleccionadas y reutiliza los
datos de la última consulta.

### `generate_chart`

Genera un gráfico a partir de los datos obtenidos mediante
`execute_query`.

Los tipos soportados son:

-   `line`
-   `bar`
-   `scatter`

La ubicación del archivo generado está controlada por el código.

## Evidencia de los frenos

### Máximo de pasos

Configuración:

``` python
agent = MyAnalystAgentLangGraph(
    max_steps=2,
    token_budget=10000,
    repeat_limit=3
)
```

Resultado:

``` text
status: max_steps_reached
answer: No pude completar la tarea dentro del limite de pasos.
trace: 2 pasos
```

El agente no devuelve una respuesta vacía y termina mediante el nodo
`tope`.

### Presupuesto de tokens

Configuración:

``` python
agent = MyAnalystAgentLangGraph(
    max_steps=8,
    token_budget=100,
    repeat_limit=3
)
```

Resultado:

``` text
status: token_budget_reached
answer: No pude completar la tarea porque se alcanzó el presupuesto de tokens.
```

La comprobación se realiza antes de efectuar una nueva llamada al
modelo.

### Detector de repetición

Se utilizó un modelo simulado que solicitaba repetidamente:

``` json
{
  "name": "execute_query",
  "args": {
    "query": "SELECT 1"
  }
}
```

Con:

``` python
repeat_limit=3
```

el agente ejecutó tres veces la misma acción y bloqueó la cuarta.

Resultado:

``` text
status: repetition_detected
answer: No pude completar la tarea porque detecté una repetición de la misma herramienta.
```

**Limitación del detector:** detecta únicamente repeticiones exactas de
la misma herramienta con exactamente los mismos argumentos. No detecta
bucles semánticamente equivalentes donde, por ejemplo, el modelo genera
consultas SQL diferentes que producen esencialmente el mismo resultado.

## Conclusión

La Parte 4 implementó el agente analítico mediante LangGraph conservando
el contrato y las restricciones de las partes anteriores.

El uso de un grafo permitió representar explícitamente el ciclo:

``` text
modelo → herramienta → modelo
```

y las condiciones de terminación mediante nodos y aristas.

La evaluación con el mismo golden set mostró que la nueva implementación
conserva una exactitud del 100 % sobre las preguntas respondibles y una
abstención correcta del 100 %, sin abstenciones indebidas ni
excepciones.

Además, el promedio de pasos y la latencia total disminuyeron respecto
de la Parte 2.

La principal mejora de esta parte es, por tanto, la **orquestación
explícita del flujo mediante un grafo de estados**, manteniendo las
garantías y métricas de calidad del agente anterior.
