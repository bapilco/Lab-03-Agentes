# Parte 1 — Agente analítico con herramientas

## 1. Código del agente

Se implementó el agente analítico mediante un bucle iterativo entre el modelo y las herramientas.

Archivos principales:
- `agent.py`: contiene `AnalystAgent`, el prompt, las definiciones de herramientas, el bucle, manejo de errores y trazas.
- `tools.py`: contiene `execute_query`, `compute_statistics` y `generate_chart`.

El agente se ejecuta con `AnalystAgent().run(question)` y devuelve `answer`, `trace`, `status`, `model` y `usage`. Las trazas se almacenan en `traces/`.

## 2. Herramientas

### `execute_query`
Ejecuta consultas SQL de solo lectura sobre SQLite.

**Entrada:**
```json
{"query": "string"}
```

Solo acepta una sentencia `SELECT` o `WITH ... SELECT`, utiliza SQLite en modo `read-only` y limita los resultados a 50 filas.

### `compute_statistics`
Calcula estadísticas descriptivas de las columnas numéricas obtenidas por la consulta.

**Entrada:**
```json
{"columns": ["columna1", "columna2"]}
```

Los datos se toman internamente del resultado de `execute_query`.

### `generate_chart`
Genera un gráfico a partir de los datos obtenidos.

**Entrada:**
```json
{"x": "columna_x", "y": "columna_y", "chart_type": "line"}
```

`chart_type` puede ser `line`, `bar` o `scatter`. La ruta de salida es controlada internamente por el código.

## 3. Bucle del agente

```text
Pregunta del usuario
        ↓
       LLM
        ↓
¿Necesita herramienta?
   ┌────┴────┐
  Sí        No
   ↓         ↓
Ejecutar   Respuesta
herramienta final
   ↓
Observación
   ↓
Volver al LLM
```

La ejecución termina cuando el modelo genera una respuesta final. También puede terminar al alcanzar `max_steps = 8` o cuando ocurre un error del modelo.

## 4. Seis reglas implementadas

### Regla 1 — El modelo conoce las herramientas
El modelo recibe mediante `TOOL_DEFINITIONS` el nombre, descripción y esquema de entrada de cada herramienta.

### Regla 2 — Solo lectura real
`execute_query` utiliza SQLite en modo `read-only` y únicamente permite una sentencia `SELECT` o `WITH ... SELECT`.

### Regla 3 — Los límites los impone el código
El límite de 50 filas y la ruta del gráfico son definidos por el código y no pueden ser modificados por el modelo.

### Regla 4 — Las herramientas comparten datos
El resultado de `execute_query` se almacena en `self.tool_data["last_query"]` y puede ser reutilizado por `compute_statistics` y `generate_chart`.

### Regla 5 — Los errores no terminan automáticamente el agente
Los errores se convierten en observaciones con formato `{"error": "..."}` y se devuelven al modelo para que pueda corregir su estrategia o abstenerse.

### Regla 6 — Siempre se guarda la traza
La traza se guarda en ejecuciones exitosas, con error o al alcanzar `max_steps`. Cada paso registra modelo, tokens, latencia y error cuando corresponde.

## 5. Justificación de la regla 4

Los datos se mantienen dentro del estado interno del agente. El modelo solo decide qué herramienta utilizar y no necesita copiar las filas entre llamadas.

Esto reduce el consumo de tokens, evita modificaciones accidentales de los datos y mantiene su gestión dentro del código.
